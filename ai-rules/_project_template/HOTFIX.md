# Hotfix（緊急修正）ガイド（{{PROJECT_NAME}} 専用）

このドキュメントでは、本番環境で発生した緊急バグへの対応フローを定義します。

**プロジェクト固有**: このファイルは {{PROJECT_NAME}} プロジェクト専用の設定を含みます。

**最終更新**: {{CURRENT_DATE}}

---

## 概要

### Hotfix とは

**本番環境で発生した緊急度の高いバグ**を迅速に修正するための特別なフローです。

通常の開発ワークフローとは異なり、**スピード重視**で対応します。

### Hotfix の判断基準

以下の条件を満たす場合は Hotfix として対応：

✅ **Hotfix として対応すべき**:
- **サービス停止**: アプリケーションが動作しない
- **データ損失リスク**: データが失われる可能性がある
- **セキュリティ脆弱性**: ユーザー情報漏洩等のリスク
- **重大な機能不全**: 主要機能が全く使えない
- **大量のエラー**: 多数のユーザーに影響

❌ **通常フローで対応**:
- 一部機能の不具合（代替手段がある）
- UI の軽微なバグ
- パフォーマンスの若干の低下
- エッジケースのバグ

**迷ったらユーザーに確認**してください。

## Hotfix フロー

### 全体図

```
[本番バグ発見]
    ↓
[緊急度判定] ← Hotfix か通常対応か判断
    ↓
[hotfix-* ブランチ作成] ← main から直接作成
    ↓
[最小限の修正] ← バグ修正のみ、機能追加禁止
    ↓
[動作確認] ← 簡易テスト（5-10分）
    ↓
[コミット]
    ↓
[PR作成] ← 簡易的なPR（テンプレート簡略版）
    ↓
[緊急レビュー] ← code-reviewer（簡易モード）またはユーザー直接確認
    ↓
[即マージ → 本番デプロイ] ← 最優先でデプロイ
    ↓
[動作確認]
    ↓
[ドキュメント更新] ← docs-updater
    ↓
[ポストモーテム作成] ← 原因分析・再発防止策
```

## 1. 本番バグ発見・報告

### 1.1 バグ報告受領

**情報収集**:
- 発生日時
- 影響範囲（全ユーザー or 一部）
- エラーメッセージ
- 再現手順
- スクリーンショット

### 1.2 緊急度判定

| レベル | 対応 | 例 |
|--------|------|-----|
| **Critical** | 即座に Hotfix | サービス停止、データ損失 |
| **High** | Hotfix（1時間以内） | 主要機能不全 |
| **Medium** | 通常フロー（当日中） | 一部機能不具合 |
| **Low** | 通常フロー（計画的） | 軽微なバグ |

## 2. Hotfix ブランチ作成

### 2.1 ブランチ作成

⚠️ **重要**: **main ブランチから直接作成**

```bash
# main ブランチを最新に
git checkout main
git pull origin main

# hotfix ブランチ作成
git checkout -b hotfix-<バグの簡潔な説明>

# 例:
# git checkout -b hotfix-login-500-error
# git checkout -b hotfix-payment-failure
# git checkout -b hotfix-data-loss-on-delete
```

### 2.2 ブランチ命名規則

```
hotfix-<バグの簡潔な説明>
```

**良い例**:
- `hotfix-login-500-error`
- `hotfix-payment-failure`
- `hotfix-null-pointer-crash`

**悪い例**:
- `fix-bug`（何のバグか不明）
- `emergency`（内容が不明）
- `hotfix-20250110`（日付だけ）

## 3. 最小限の修正

### 3.1 修正方針

✅ **すべきこと**:
- **バグ修正のみ**に集中
- 最小限のコード変更
- 影響範囲を限定

❌ **してはいけないこと**:
- 機能追加
- リファクタリング
- 無関係なコードの修正
- 大規模な変更

### 3.2 コード修正

```bash
# 該当ファイルを修正
# - バグの原因箇所のみ修正
# - 最小限の変更に留める
```

### 3.3 動作確認（簡易）

⚠️ **通常のE2Eテストはスキップ可**（時間優先）

**最低限の確認**:
- [ ] バグが修正されたか確認（5分）
- [ ] 主要フローが壊れていないか確認（5分）
- [ ] コンソールエラーがないか確認

**ローカル環境で確認**:
```bash
# フロントエンド
cd frontend && npm run dev

# バックエンド
cd backend && [起動コマンド]

# 修正箇所を中心に動作確認
```

## 4. コミット・PR作成

### 4.1 コミット

```bash
git add .
git commit -m "hotfix: <バグの簡潔な説明>

[緊急修正] <詳細な説明>

- 原因: <バグの原因>
- 修正内容: <何を修正したか>
- 影響範囲: <どこに影響するか>

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>"
```

**例**:
```bash
git commit -m "hotfix: ログイン時の500エラーを修正

[緊急修正] null チェック漏れによる500エラーを修正

- 原因: ユーザー情報が null の場合のハンドリング不足
- 修正内容: null チェックを追加
- 影響範囲: ログイン処理のみ

🤖 Generated with [Claude Code](https://claude.com/claude-code)

Co-Authored-By: Claude <noreply@anthropic.com>"
```

### 4.2 Push

```bash
git push -u origin hotfix-<バグの簡潔な説明>
```

### 4.3 PR作成（簡易版）

```bash
gh pr create --title "hotfix: <バグの簡潔な説明>" --body "$(cat <<'EOF'
## 🚨 緊急修正（Hotfix）

### バグの概要
<バグの説明>

### 原因
<バグの原因>

### 修正内容
<何を修正したか>

### 影響範囲
<どこに影響するか>

### 動作確認
- [x] バグが修正されたことを確認
- [x] 主要フローが壊れていないことを確認

### 緊急度
- [ ] Critical（即座に対応必須）
- [ ] High（1時間以内に対応）

🤖 Generated with [Claude Code](https://claude.com/claude-code)
EOF
)"
```

## 5. 緊急レビュー

### 5.1 code-reviewer（簡易モード）

**通常のレビューより簡略化**:

```
> code-reviewerサブエージェントを使用してPR #[番号]をレビューしてください
> （Hotfix のため簡易レビュー）
```

**レビュー観点**:
- ✅ バグが修正されているか
- ✅ 他の機能を壊していないか
- ✅ セキュリティリスクがないか

**スキップ可能**（時間優先の場合）:
- 命名規則の細かいチェック
- パフォーマンス最適化の提案
- リファクタリング提案

### 5.2 ユーザー直接確認（オプション）

Critical の場合、ユーザーに直接確認を求めることも可：

```
ユーザー様

緊急修正が完了しました。
以下のブランチで動作確認をお願いできますでしょうか。

ブランチ: hotfix-<バグの簡潔な説明>
確認URL: [ステージング or プレビューURL]

確認いただけ次第、本番へデプロイします。
```

## 8. Hotfix チェックリスト

### 修正前
- [ ] 本番バグであることを確認
- [ ] 緊急度が High 以上であることを確認
- [ ] ユーザーへの影響を把握
- [ ] main ブランチから hotfix ブランチ作成

### 修正中
- [ ] 最小限の変更に留める
- [ ] バグ修正のみ（機能追加禁止）
- [ ] ローカルで動作確認

### デプロイ前
- [ ] コミット・PR作成
- [ ] 簡易レビュー（code-reviewer or ユーザー）
- [ ] ロールバック手順確認

### デプロイ後
- [ ] 本番動作確認
- [ ] ユーザーへ通知
- [ ] ドキュメント更新
- [ ] ポストモーテム作成（24時間以内）
- [ ] 再発防止策 Issue 作成

## 9. トラブルシューティング

### Hotfix 後も問題が解決しない

1. **即座にロールバック**
   ```bash
   # 詳細: DEPLOYMENT.md のロールバック手順
   ```

2. **別の原因を調査**
   - エラーログ確認
   - 監視ツール確認
   - ユーザーからの追加情報

3. **再度 Hotfix 実施**

### 複数のバグが同時発生

1. **優先度順に対応**
   - Critical → High → Medium の順

2. **並行作業は避ける**
   - 1つずつ確実に修正

3. **必要に応じてロールバック**
   - 修正が複雑な場合は一旦戻す
