## 3. バックアップ・復旧

### 3.1 バックアップ戦略

| 対象 | 頻度 | 保持期間 | 方法 |
|------|------|----------|------|
| **データベース** | 毎日（自動） | 30日 | フルバックアップ |
| **ユーザーアップロードファイル** | 毎日（自動） | 90日 | 差分バックアップ |
| **設定ファイル** | 変更時 | 無期限（Git） | Git管理 |
| **環境変数** | 変更時 | 無期限（ドキュメント） | docs/ENV_VARS.md |

### 3.2 データベースバックアップ

#### 手動バックアップ

```bash
# PostgreSQL の例
pg_dump -h {{DB_HOST}} -U {{DB_USER}} -d {{DB_NAME}} > backup_$(date +%Y%m%d_%H%M%S).sql

# 保存先
# {{BACKUP_STORAGE}}/db/

# MySQL の例
mysqldump -h {{DB_HOST}} -u {{DB_USER}} -p {{DB_NAME}} > backup_$(date +%Y%m%d_%H%M%S).sql
```

#### 自動バックアップ設定

```bash
# cron 設定例（毎日 3:00 AM）
0 3 * * * /path/to/backup_script.sh

# backup_script.sh の内容:
#!/bin/bash
BACKUP_DIR={{BACKUP_STORAGE}}/db
DATE=$(date +%Y%m%d)
pg_dump -h {{DB_HOST}} -U {{DB_USER}} -d {{DB_NAME}} | gzip > $BACKUP_DIR/backup_$DATE.sql.gz

# 30日以上前のバックアップを削除
find $BACKUP_DIR -name "backup_*.sql.gz" -mtime +30 -delete
```

### 3.3 データベース復旧

⚠️ **超重要**: 本番環境での復旧は慎重に実施

```bash
# 1. メンテナンスモード開始（ユーザーアクセス停止）
# [メンテナンスモード開始コマンド]

# 2. 現在のDBをバックアップ（念のため）
pg_dump -h {{DB_HOST}} -U {{DB_USER}} -d {{DB_NAME}} > pre_restore_backup.sql

# 3. データベース復元
# PostgreSQL
psql -h {{DB_HOST}} -U {{DB_USER}} -d {{DB_NAME}} < backup_{{DATE}}.sql

# MySQL
mysql -h {{DB_HOST}} -u {{DB_USER}} -p {{DB_NAME}} < backup_{{DATE}}.sql

# 4. 整合性確認
# [確認クエリ]

# 5. メンテナンスモード解除
# [メンテナンスモード解除コマンド]
```

### 3.4 ファイルバックアップ

```bash
# ユーザーアップロードファイル等

# S3 へのバックアップ例
aws s3 sync {{UPLOAD_DIR}} s3://{{BACKUP_BUCKET}}/uploads/$(date +%Y%m%d)/

# rsync でのバックアップ例
rsync -avz {{UPLOAD_DIR}} {{BACKUP_SERVER}}:{{BACKUP_PATH}}/
```

## 4. 障害対応フロー

### 4.1 障害検知

**検知方法**:
1. 監視アラート
2. ユーザー報告
3. 定期チェック

### 4.2 初動対応（5分以内）

```
[障害検知]
    ↓
[影響範囲確認] ← 全ユーザー or 一部？
    ↓
[緊急度判定] ← Critical / High / Medium
    ↓
    ├─ Critical → [即座にロールバック検討]
    ├─ High → [Hotfix 準備]
    └─ Medium → [原因調査優先]
```

### 4.3 障害対応チェックリスト

- [ ] **検知（0分）**: アラート or 報告受領
- [ ] **初動（5分以内）**: 影響範囲・緊急度確認
- [ ] **暫定対応（10分以内）**: ロールバック or 緊急修正
- [ ] **復旧確認（15分以内）**: サービス復旧確認
- [ ] **ユーザー通知（20分以内）**: 状況報告
- [ ] **原因調査（1時間以内）**: 根本原因特定
- [ ] **恒久対策（24時間以内）**: 再発防止策実施
- [ ] **ポストモーテム（24時間以内）**: 振り返り文書作成

### 4.4 ロールバック判断

**即座にロールバック**:
- サービス全停止
- データ損失の可能性
- セキュリティ脆弱性

**原因調査優先**:
- 一部機能の不具合
- パフォーマンス低下（軽微）

詳細: [DEPLOYMENT.md](./DEPLOYMENT.md) のロールバック手順
